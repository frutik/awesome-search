Elasticsearch API served from Qdrant

An Elasticsearch application can keep its client code and change the engine underneath it. qdrant-es-gateway is a Rust gateway that does this for Qdrant: it serves a subset of the Elasticsearch REST API, scores text with Qdrant's server-side BM25 sparse model, and rejects unsupported features such as scripts and scroll with explicit errors. On its author's own run over 500,000 generated products at 50 clients, it searched faster than Elasticsearch, used about 43× the storage, and did not reproduce Elasticsearch's top-ranked results. Migration between Search Engines now covers API-compatibility gateways as an option alongside rewriting clients. Built by David Stockton.

Diversity built into inner-product search

Top-k inner-product search returns the most relevant vectors and, left alone, the most alike ones: in one MovieLens example, a user with ten rated genres got recommendations from five. Diversity-Aware k-Maximum Inner Product Search Revisited covers DkMIPS, which moves the MMR trade-off inside Maximum Inner Product Search — a λ dial between relevance and average or maximum pairwise similarity, greedy algorithms with a 1/4 approximation guarantee for the average form, and tree-based pruning, since standard ANN indexes don't fit the pairwise term. DiversiNews, its news demo over the NewsSpectrum corpus, measures diversity as a spread of outlet bias ratings. By Qiang Huang, Yanhao Wang, Yiqun Sun and Anthony K.H. Tung; all performance figures are the authors' own.

ESCI as a label scheme

A product search result can be the thing asked for, a stand-in for it, an accessory to it, or unrelated — and binary relevance cannot tell those apart. ESCI Label Scheme covers the Exact / Substitute / Complement / Irrelevant grading introduced with the Amazon ESCI Dataset and how it has travelled without the data: Allegro's judgment guidelines were inspired by it, Etsy plans the same substitute/complement split, and sQuIrRel's relevance model predicts its labels. It also covers where the grades are hard: in Allegro's tests, an LLM judge reached F1 around 0.94 on exact matches but only 0.33–0.51 when separating degrees of substitutability.

sQuIrRel: query-classifier labels from relevance

Evaluating a query-to-product-type classifier needs labels for thousands of product types, and neither clicks nor annotators supply them well. sQuIrRel, from Amazon, derives them from relevance instead: a high-precision model keeps each query's exact-match results, and the query inherits their dominant catalogue product type. A manual check of 400 queries found 87% of labels correct, with complements as the main error. The paper publishes only the procedure, built on internal Amazon data. Its limits: it skips multi-intent queries and can only label queries where the engine already returns the right products.

E-commerce search evaluation datasets compared

Public product-search datasets differ less in size than in what a relevance label means. ESCI separates substitutes from complements, WANDS folds both into one Partial grade, and Home Depot averages annotator scores on a continuous scale. E-commerce Search Evaluation Datasets compares them alongside ESCI-S and its decaying image links, and matches each to the catalogs and query styles it suits. It also collects the cross-catalog evidence: in one fine-tuning series, an ESCI-tuned SPLADE model gained 27.5% nDCG@10 over BM25 on ESCI itself, but only 8–10% on WANDS and Home Depot.
